# Supported Operating Systems and Installers

Reference for Rainforest's supported desktop platforms, architectures, package formats, and auto-update artifacts built with MyGo v0.4.8 (`CGO_ENABLED=0`).

## Platform Matrix

| Operating System | Architecture (`GOOS/GOARCH`) | Primary Bundle / Binary | Installer / Package Artifacts | Signed Auto-Update Manifest |
|---|---|---|---|---|
| **macOS 12.0+** | Apple Silicon (`darwin/arm64`) | `Rainforest.app` | `Rainforest <ver> arm64.dmg` (when signed) + `rainforest-darwin-arm64.tar.gz` | `update-darwin-arm64.json` |
| **macOS 12.0+** | Intel (`darwin/amd64`) | `Rainforest.app` | `Rainforest <ver> amd64.dmg` (when signed) + `rainforest-darwin-amd64.tar.gz` | `update-darwin-amd64.json` |
| **Windows 10/11** | x64 (`windows/amd64`) | `Rainforest.exe` | `Rainforest Setup <ver> amd64.exe` (with NSIS) + `rainforest-windows-amd64.zip` | `update-windows-amd64.json` |
| **Windows 11** | ARM64 (`windows/arm64`) | `Rainforest.exe` | `Rainforest Setup <ver> arm64.exe` (with NSIS) + `rainforest-windows-arm64.zip` | `update-windows-arm64.json` |
| **Linux** | x64 (`linux/amd64`) | `rainforest` + `rainforest.desktop` | `rainforest_<ver>_amd64.deb`, `rainforest-<ver>-linux-amd64.tar.gz`, `install.sh` | `update-linux-amd64.json` |
| **Linux** | ARM64 (`linux/arm64`) | `rainforest` + `rainforest.desktop` | `rainforest_<ver>_arm64.deb`, `rainforest-<ver>-linux-arm64.tar.gz`, `install.sh` | `update-linux-arm64.json` |

## Auto-Update Signing (`mygo.config.ts`)

- `updates.publicKey`: Embedded Ed25519 public key (`Ykj6GObFAitTNBjip51D96NsOrUx1aUbP9j5yy+cJ8s=`) generated by `mygo keygen`.
- `MYGO_UPDATER_PRIVATE_KEY`: CI/Release secret used by `mygo build` to sign `rainforest-<ver>-<os>-<arch>.tar.gz` update archives and emit `update-<os>-<arch>.json`.
- When `MYGO_UPDATER_PRIVATE_KEY` is absent (for example in fork PR builds), `mygo build` builds the platform application bundles and skips generating signed update manifests with a clear notice rather than failing or fabricating unsigned manifests.

## v0.1.0 Release Acceptance

The following checks were performed on the published v0.1.0 Apple Silicon archive on 2026-10-14:

| Check | Result |
|---|---|
| macOS package | `.app` in `.tar.gz`; no `.dmg` published |
| Bundle integrity (`codesign --verify --deep --strict`) | Passed |
| Signing identity (`codesign -dv --verbose=4`) | Ad-hoc; no TeamIdentifier or Developer ID |
| Notarization ticket (`xcrun stapler validate`) | No stapled ticket |
| Gatekeeper first installation | Unverified: the test machine has assessments disabled |
| CI signing setup | Only the updater private-key secret is configured; Apple signing and notarization secrets are absent |
| In-app update | Signed manifest published; complete download, replacement, restart, and rollback flow unverified |
| Backup, tray, permissions, real-account upload and recovery | End-to-end acceptance pending |

The update manifest signature authenticates update archives; it does not provide Apple Developer ID signing or notarization. macOS distribution acceptance requires a Developer ID Application identity, configured notarization credentials, and a fresh installation test with Gatekeeper enabled. A `.dmg` alone does not satisfy these requirements.
