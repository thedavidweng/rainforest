# Supported Operating Systems and Installers

Reference for Rainforest's supported desktop platforms, architectures, package formats, and auto-update artifacts built with MyGo v0.5.1 (`CGO_ENABLED=0`).

## Platform Matrix

| Operating System | Architecture (`GOOS/GOARCH`) | Primary Bundle / Binary | Installer / Package Artifacts | Signed Auto-Update Manifest |
|---|---|---|---|---|
| **macOS 12.0+** | Apple Silicon (`darwin/arm64`) | `Rainforest.app` | `Rainforest <ver> arm64.dmg` (when signed) + `rainforest-darwin-arm64.tar.gz` | `update-darwin-arm64.json` |
| **macOS 12.0+** | Intel (`darwin/amd64`) | `Rainforest.app` | `Rainforest <ver> amd64.dmg` (when signed) + `rainforest-darwin-amd64.tar.gz` | `update-darwin-amd64.json` |
| **Windows 10/11** | x64 (`windows/amd64`) | `Rainforest.exe` | `Rainforest Setup <ver> amd64.exe` (with NSIS) + `rainforest-windows-amd64.zip` | `update-windows-amd64.json` |
| **Windows 11** | ARM64 (`windows/arm64`) | `Rainforest.exe` | `Rainforest Setup <ver> arm64.exe` (with NSIS) + `rainforest-windows-arm64.zip` | `update-windows-arm64.json` |
| **Linux** | x64 (`linux/amd64`) | `rainforest` + `rainforest.desktop` | `rainforest_<ver>_amd64.deb`, `rainforest-<ver>-linux-amd64.tar.gz`, `install.sh`, `rainforest-<ver>-x86_64.AppImage` + `.AppImage.zsync` | `update-linux-amd64.json` |
| **Linux** | ARM64 (`linux/arm64`) | `rainforest` + `rainforest.desktop` | `rainforest_<ver>_arm64.deb`, `rainforest-<ver>-linux-arm64.tar.gz`, `install.sh` | `update-linux-arm64.json` |

## Linux AppImage

The x86_64 AppImage is built on Ubuntu 22.04 in addition to the existing Debian packages, tar archives, install scripts, and ARM64 outputs. GTK, WebKitGTK libraries/helpers, and GTK resources are bundled explicitly because MyGo loads native libraries dynamically rather than through ELF dependencies. The host still supplies its graphics driver stack and normal desktop services.

Each AppImage embeds `gh-releases-zsync|thedavidweng|rainforest|latest|rainforest-*-x86_64.AppImage.zsync`. The adjacent `.AppImage.zsync`, both individual SHA-256 files, and `checksums.txt` are published together. AppImageUpdate can use this metadata to find and delta-update the latest x86_64 AppImage; it does not add a Rainforest in-app updater, nor replace MyGo's signed tarball update channel. Keep the AppImage in a user-writable directory for external updates.

CI and release jobs extract the actual AppImage, reject unreadable/non-executable package paths and missing dynamic libraries, and launch the artifact under Xvfb in a fresh HOME as UID 10001 with no network on Ubuntu 22.04. A visible, correctly sized Rainforest main window owned by its executable and an initialized SQLite database are required; `--version` alone is insufficient. This smoke covers offline startup, not Amazon sign-in or real-account transfers. `mise run test-release` exercises packaging permission and launcher boundaries without building an AppImage.

To reproduce on x86_64 Ubuntu 22.04 after installing the Go toolchain:

```sh
bash scripts/install-appimage-tools.sh "$PWD/.appimage-tools"
export PATH="$PWD/.appimage-tools:$PATH"
go tool mygo build -platform linux/amd64 -skip-dmg -skip-notarize -o dist
bash scripts/build-appimage.sh dist/linux-amd64 dist/linux-amd64
docker build -f packaging/appimage/smoke.Dockerfile -t rainforest-appimage-smoke .
image=$(realpath dist/linux-amd64/rainforest-*-x86_64.AppImage)
docker run --rm --network none --cap-drop ALL --security-opt no-new-privileges \
  -v "$PWD/dist/linux-amd64:/artifacts:ro" -v "$PWD/scripts:/checks:ro" \
  rainforest-appimage-smoke "/artifacts/${image##*/}"
```

## Auto-Update Signing (`mygo.config.ts`)

- `updates.publicKey`: Embedded Ed25519 public key (`Ykj6GObFAitTNBjip51D96NsOrUx1aUbP9j5yy+cJ8s=`) generated by `mygo keygen`.
- `MYGO_UPDATER_PRIVATE_KEY`: CI/Release secret used by `mygo build` to sign `rainforest-<ver>-<os>-<arch>.tar.gz` update archives and emit `update-<os>-<arch>.json`.
- When `MYGO_UPDATER_PRIVATE_KEY` is absent (for example in fork PR builds), `mygo build` builds the platform application bundles and skips generating signed update manifests with a clear notice rather than failing or fabricating unsigned manifests.

## macOS Release Signing

Tagged releases require these GitHub Actions secrets:

- `APPLE_CERTIFICATE_P12_BASE64`: base64-encoded Developer ID Application certificate and its private key.
- `APPLE_CERTIFICATE_PASSWORD`: password for that P12.
- `APPLE_API_KEY_BASE64`: base64-encoded App Store Connect `.p8` key.
- `APPLE_API_KEY_ID` and `APPLE_API_ISSUER`: that API key's identifiers.

The release workflow imports `Developer ID Application: MOE AI LLC (NCFNX3LJ83)` into a temporary keychain and stores the API credentials there for MyGo's notarization profile. Missing credentials stop the macOS jobs. MyGo signs with hardened runtime and a timestamp, notarizes and staples the DMG, then staples the App before generating the update archive and its Ed25519 signature. The workflow verifies both artifacts' signatures, team, stapled tickets, and Gatekeeper assessments before packaging or uploading. Credentials are removed even when the build fails.

Run `mise run test-release` to exercise the verification gate with controlled Apple tool responses. These tests do not establish Apple's acceptance of a release. Local unsigned builds retain `go tool mygo build -skip-dmg -skip-notarize`.

## v0.1.0 Release Acceptance

The following checks were performed on the published v0.1.0 Apple Silicon archive on 2026-10-14:

| Check | Result |
|---|---|
| macOS package | `.app` in `.tar.gz`; no `.dmg` published |
| Bundle integrity (`codesign --verify --deep --strict`) | Passed |
| Signing identity (`codesign -dv --verbose=4`) | Ad-hoc; no TeamIdentifier or Developer ID |
| Notarization ticket (`xcrun stapler validate`) | No stapled ticket |
| Gatekeeper first installation | Unverified: the test machine has assessments disabled |
| CI signing setup | Only the updater private-key secret is configured; Apple signing and notarization secrets are absent |
| In-app update | Signed manifest published; complete download, replacement, restart, and rollback flow unverified |
| Backup, tray, permissions, real-account upload and recovery | End-to-end acceptance pending |

The update manifest signature authenticates update archives; it does not provide Apple Developer ID signing or notarization. macOS distribution acceptance requires a Developer ID Application identity, configured notarization credentials, and a fresh installation test with Gatekeeper enabled. A `.dmg` alone does not satisfy these requirements.
